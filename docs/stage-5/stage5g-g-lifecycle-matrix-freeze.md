## Scope

Stage 5G-g freezes the 54 accepted paper/mock lifecycle scenarios from Stage
5G-b through Stage 5G-f. It does not add lifecycle semantics. Stage 5G-f stays
closed and immutable. Redis live consumption, FINAM transport, broker dispatch,
runtime-live, real orders, native stop/SLTP/bracket and Stage 6 stay closed.

The aggregate artifact has one ordered row per frozen scenario:

- ACK: 10;
- order/trade/position: 16;
- timer: 8;
- restart/reconciliation: 12;
- protective completion: 8.

## Evidence rule

The artifact distinguishes two evidence kinds:

1. `source_produced_runtime_artifact` is generated by an accepted owning
   lifecycle boundary and may populate runtime/restart/cleanup fingerprints.
2. `executable_accepted_witness` identifies an exact accepted executable
   witness. It must not fabricate runtime fingerprints. For accepted owners
   without a stable artifact API, runtime fields remain `null` and the exact
   witness tuple is the frozen authority.

The accepted Stage 5G-f GPRT artifact satisfies the first rule for all eight
protective rows. Stage 5G-g adds narrow source-produced adapters for all ten ACK
and all sixteen order/position rows. The accepted timer and restart owners do
not export a stable runtime-artifact API. Their twenty rows therefore remain
exact executable-witness bindings and are run in both debug and release by the
Stage 5G-g gate. Stage 5G-g deliberately leaves unavailable runtime/package
fields `null` instead of inventing fingerprints or reopening accepted 5G-d/e
semantics merely for evidence plumbing. This follows the accepted stage
governance rule: evidence hardening belongs to the transition gate and does not
reopen a closed functional slice.

## Internal implementation order

1. Freeze the common schema, exact 54-row ordering and witness bindings.
2. Add source-produced adapters where an owning source API exists (ACK and
   order/position); bind and execute the exact accepted timer/restart witnesses
   where no stable artifact API exists.
3. Require complete pre/post runtime, lifecycle checkpoint, restart/package,
   callback, generated-intent/cleanup and final owner/cycle/position evidence
   wherever the scenario reaches those boundaries. A field may remain absent
   only when the scenario blocks before that authority exists, and the typed
   disposition must prove why.
4. Run exact debug, release and default-parallel byte equivalence.
5. Add aggregate mutation guards, preseal and immutable handoff evidence.

Independent review is requested only after steps 1–5 are complete.
