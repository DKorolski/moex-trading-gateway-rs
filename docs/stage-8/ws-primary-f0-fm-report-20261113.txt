КАРТА ПОЛЕЙ F0
Expected label/nominal close: отдельный production model-day, +600000 ms.
Source и admission reason: canonical_source.receipt (canonical для recovery).
Minute completeness: actual_m1.length, minute_bitmap; никакого gap fill.
Current generation: receipt.generation и соответствующий readiness snapshot.
Boundary/grace: receipt и последний snapshot до фактического source selection.
WS candidate: только записанный WS_READY_CANDIDATE до selection, не вычисленная
задним числом дата. При отсутствии witness время готовности невыбранного WS
неизвестно. Readiness diagnostic сам по себе не является admission capability.
REST choice: primary_precommit_rest_selected + source reason + preceding
readiness + REST outcome. Отсутствующее объяснение остаётся неизвестным.
REST audit/revision сохраняется отдельно и не заменяет canonical input.
Source -> step -> feedback при intent -> commit связываются label, hashes,
порядком строк и фактическими refs: sequence, byte offset, exact line SHA.
Source/native admission hashes не пересчитываются новым Python report:
для этого сохраняется штатный pinned Rust reader.

КАРТА ПОЛЕЙ FM
Step.before = состояние перед моделью.
Step.after = состояние сразу после решения, ДО candle feedback.
hypothetical_candle_feedback.state_after = состояние после исполнения и
обратного on_broker_position. Отсутствующая фаза null с явной причиной.
Request.sequence записан в fill.request; в Step отдельного request ID нет.
Сцепление с решением выполняется по label/hash/action/quantity и порядку строк;
новый native intent ID не изобретается. Повторный fill sequence — finding.
No action сохраняет реальный reason, а не выводится из отсутствия заявки.
LIVE_OBSERVED Step содержит measured clock; BACKFILL_REPLAY Step clock виртуален.
Actual recovery start/result доступны в recovery_step_durable_publication и
canonical_commit; они не подменяются virtual nominal close.
Позиция/pending в summary — последнее записанное состояние, не EOD verdict.
Неверная phase, missing/duplicate feedback, hash/order/position mismatch
отмечаются как findings и не меняют исходный runtime.
