3. Новые замечания

R3 — P2: normalizer и live session несовместимы по точности quote timestamps.

Места:
- crates/finam-signal-shadow/src/quote.rs:122–125, 142–160;
- crates/finam-signal-shadow/src/session.rs:338–346;
- prefix handoff floor устанавливается в session.rs:114–116.

QuoteInput принимает и различает полные DateTime timestamps, в том числе
субмиллисекундные, но Quote.event_at_ms получается через timestamp_millis().
Session теперь требует строгое увеличение миллисекунд для каждой live quote:
event_at_ms <= last_quote_ms вызывает terminal SessionError::Input.
Это правило действует и на fresh observe, не только после prefix.

Допустимый сценарий одного frame:
- timestamp 10:00:00.000100Z, last=2200;
- timestamp 10:00:00.000200Z, last=2200.5;
- receive 10:00:00.001Z.
При подходящем run window/age оба события проходят normalizer, получают разные
source IDs, но одинаковый event_at_ms. Session принимает первое и завершает
сегмент на втором, даже при flat/no-pending. Фактическую точность FINAM reviewer
не утверждает; дефект — противоречие между поддерживаемыми внутренними входами.
До R1 session отвергал только event_at_ms < last; строгий prefix floor был
распространён на весь live ordering.

Минимальная коррекция: отделить неизменяемый strict cross-prefix floor от
обычной within-live chronology либо сохранить полную точность. При варианте
с миллисекундами source-level dedup остаётся full-precision, а несколько
различных admitted quotes внутри одной ms не должны закрывать session.
Если выбирается ms-only контракт, его нужно явно валидировать у входа и
обосновать для выбранного provider build; молчаливое усечение не подходит.

Acceptance: adapter→ObservedSession test с двумя разными timestamps в одной ms,
включая flat/pending; не более одного feedback effect на intent. Отдельно
сохранить отказ/неприменение old prefix quote и существующие conflict checks.
Не смешивать прохождение chronology с разрешением fill: quote <= decision
по-прежнему не должен заполнять новый intent.

R4 — P2: prefix replay отвергает корректный порядок из собственного runner.

Места:
- crates/finam-signal-shadow/src/prefix.rs:219–225, 245–253, 305–314, 353;
- crates/finam-signal-shadow/src/runner.rs:351–380, 393–410;
- узкий сериализованный fixture: tests/restart.rs:182–205.

Prefix требует received_at >= clock, где clock — предыдущий глобальный
result_at_ms/applied_at_ms. Runner получает REST и QUOTES независимыми workers,
а coordinator применяет уже полученные события последовательно через очередь.
Receive time следующего обрабатываемого события может предшествовать завершению
предыдущего callback, без clock rollback и без нарушения причинности.

Сценарий, где T — nominal M10 close:
- REST response получен в T+5ms, model result — T+10ms.
- QUOTES frame с source event T+7ms получен другим worker в T+8ms.
- Coordinator обрабатывает его в T+12ms. Он старше decision и корректно не
  заполняет новый intent.
Effects идут по порядку: result10 → apply12. Inventory полон и допустим для live
path. Prefix отказывает на received8 < previous_effect10.
Обратный overlap — REST response принят до применения предыдущей котировки,
но callback исполняется позже — отвергается аналогично.

Перестановка событий или исправление сохранённых receive timestamps изменяет
историю; удаление ineligible quote нарушает требуемую полноту inventory.

Минимальная коррекция: разделить глобальный порядок effects и chronology
приёма. Сохранить монотонный result/applied clock, receive <= собственный
result/applied, source-specific ordering и необходимые range/clock checks.
Глобального receive >= previous effect для независимых каналов не требовать.

Acceptance: оба queue-overlap cases с теми же raw evidence и исходными receive
timestamps; reconstructed state/pending/position/side-used совпадают с
непрерывной processing sequence. Ineligible pre-decision quote не создаёт fill.
Негативные clock/range/coverage tests и BACKFILL-only classification сохранить.
Для этого достаточно направленных local tests; live FINAM запуск не требуется.
