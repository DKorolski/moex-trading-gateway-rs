2. P1-O3-REL-R01 — directory durability не восстанавливается на retry

Места:
- scripts/stage8b_p1f_o3_readmission_install.py:195 — при совпадающих bytes
  atomic_write пропускается.
- тот же файл:196 — после verify_files/invariants записывается terminal journal.
- scripts/stage8b_p1f_o2_install.py:161 — fsync временного файла;
  :162 — os.replace; :163 — sync_dir каталога.
- scripts/test_stage8b_p1f_o3_readmission_install.py:119 —
  текущая fault-инъекция происходит после полного atomic_write,
  то есть уже после успешного directory fsync.

Воспроизводимый сценарий:
1. Новая транзакция имеет PREPARED; установленный контур остановлен.
2. Пять ELF последовательно заменяются. На последнем ELF rename уже видим,
   но процесс прекращается или directory fsync возвращает ошибку до завершения.
3. При resume все пять ELF читаются как exact-new. Условие :195 пропускает
   их atomic_write, поэтому /usr/local/libexec/moex не синхронизируется.
4. Два manifest записываются в /usr/local/share/moex/stage8b-p1e;
   terminal journal APPLIED — в отдельный TX directory.
5. Успешный terminal commit не устанавливает требуемую durability последнего
   ELF rename. При последующем OS/power crash замена может потеряться,
   несмотря на сохранённый APPLIED; штатный resume остановится на mismatch.

Rollback имеет симметричную границу: после видимого rename последнего ELF
retry может записать ROLLED_BACK без повторного directory fsync ELF parent.

Это один P1 в installer, не повтор прежнего замечания к Rust proof:
P1-O3-R01 в accepted source остаётся закрытым.

Локальное доказательство reviewer выполнено на actual Update.transition,
secure reads, atomic_write и sync_dir, с public synthetic payloads/temp-root.
Host observations и locks stubbed; production ELF не запускались.
Инъекция OSError(EIO) сделана непосредственно перед parent fsync после
последнего ELF rename. Это не эксперимент с физическим отключением питания.

Полученный trace:
apply: fault → PREPARED;
resume → APPLIED;
retry sync_dir:
  usr/local/share/moex/stage8b-p1e
  usr/local/share/moex/stage8b-p1e
  usr/local/share/moex/stage8b-p1e/o3-readmission-5df1c88-after-completed-26
ELF parent resynchronized: False.

rollback: fault → ROLLING_BACK;
rollback retry → ROLLED_BACK;
retry sync_dir: TX, manifest parent, manifest parent, TX.
ELF parent resynchronized: False.

Минимальная коррекция в новом installer:
Перед terminal journal для apply/resume и rollback проверять desired bytes,
синхронизировать все distinct replacement parents, включая parent ELF,
а также TX.parent; затем выполнять exact reread и invariants. Синхронизация
должна происходить даже когда все bytes уже совпадают. Ошибка должна выходить
до нового terminal journal, сохраняя PREPARED / ROLLING_BACK для retry.

TX.parent также нужен для retry незавершённой подготовки после mkdir:
синхронизация самого TX не заменяет durability его directory entry.

Достаточны два focused fault witness:
- apply → last ELF rename / отказ до parent fsync → resume;
- rollback → last ELF rename / отказ до parent fsync → rollback retry.
Оба должны доказывать parent fsync до terminal journal при exact desired bytes.
В каждом проверить и отказ новой финальной синхронизации: terminal не пишется,
повтор остаётся возможен. Существующие 19 installer-регрессий сохраняются.
Новая recovery architecture, native SIGKILL matrix и изменения Rust не нужны.

3. P2-O3-REL-R02 — package_file может отвергать собственное чтение

scripts/stage8b_p1f_o3_readmission_install.py:36 и :38 сравнивают полный
stat_result. Он включает atime, который может измениться от обычного read.

В нашей среде первый прогон offline runner tests на свежей копии candidate
дал package changed during read. На отдельном свежем public файле подтверждено:
из stat полей изменилась только st_atime_ns. После обычного чтения public
inputs, без изменения bytes/source, все 15 runner tests прошли.

Это fail-closed availability issue, не возможность обойти custody и не второй
блокер установки. Рекомендуемая малая коррекция: сравнивать явно dev/ino,
mode/nlink, uid/gid, size, mtime_ns/ctime_ns и соответствие открытого fd пути,
исключив atime. Сохранить single-link/type/size/custody проверки.
Один тест обычного чтения свежего файла плюс существующие tamper negatives
достаточны; расширение проекта не требуется.
