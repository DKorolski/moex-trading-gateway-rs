ПРИЧИНА ОТКАЗА ПОДТВЕРЖДЕНА

Установленный supervisor.template.json содержит 1 752 байта, включая final LF.
Guardian использует parse_canonical<serde_json::Value>: результат
serde_json::to_vec обязан совпасть с входом byte-exact. Для этого template
canonical encoding содержит 1 751 байт без final LF. Разбор JSON сам по себе
успешен, но canonical byte boundary нарушена.

Old template SHA-256:
04aed2dc5cdf5bdc44d48cf28c91986bd71e266f2965f76200caf796d87e191e
Corrected template SHA-256:
2d23f48611a02345dd5c2a6dc7d9a25a8b4c6d5a0cd4db40fabcafde6d8dc2b5

Самостоятельно подтверждено: old_bytes == corrected_bytes + LF; JSON semantic
content одинаков. Old hash совпадает с signed phase binding. Production code
проверяет canonical bytes до materialization writes. Связанный release-witness
с тем же retained staged source проходит реальный guardian materialize_o2 до
ReadyForBootstrap после исправления encoding.

Предыдущий installation input-probe проверял parseable JSON и пропустил эту
canonical boundary. Теперь он проверяет именно bytes упакованного файла и
отклоняет old LF fixture. Для этого дефекта новая архитектура не требуется.
