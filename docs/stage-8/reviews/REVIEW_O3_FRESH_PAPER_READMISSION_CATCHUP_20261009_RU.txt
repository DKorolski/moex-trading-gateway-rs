5. СОГЛАСОВАННОЕ УЗКОЕ ТЗ ДЛЯ ПРОГРАММИСТА

Цель: довести existing O3 synthetic paper path от сохранённого O2 seed до свежего решения и обычного paper lifecycle, включая exact restart. Объединить fresh re-admission и catch-up в одной source correction. Новая стадия проектирования, отдельный renewal service или общий recovery framework не нужны.

5.1. Существующий root и исторические receipts

Ordinary run admission сначала аутентифицирует сохранённые marker/receipt/seal, lifecycle и journal frontier штатным путём. Fresh readmission начального seed разрешена только для действительно initial P1SemanticReady/no-effect flat состояния: без ранее принятого торгового request, pending/working/deferred state, позиции и acquired owner.

Committed/pending continuation должна оставаться в существующей recovery classification. Её нельзя переобозначить как новый flat bootstrap, чтобы пройти допуск.

Исторические checked/issued/expires, recovery/warmup watermarks, O2 receipt, marker и first-boot source сохраняются. Нельзя подменять их текущим временем, повторять Notify/first boot/O2 Replay, менять COMPLETED/1/26, очищать root/journal/PEL или продлевать старый TTL.

Допустим штатный новый S1/semantic commit с новой authority для новой работы. Требование неизменности старой истории не означает запрета корректных будущих append.

5.2. Конкретный constructor нового допуска

Использовать production цепочку:
validate_stage4_broker_truth_bootstrap
→ build_stage4_accepted_paper_host_evidence
→ admit_stage5c_paper_host(Stage5cPaperHostAdmissionInput, allow_live_orders=false).

Нужна opaque Stage4AcceptedPaperHostEvidence; сохранённый PASS-флаг, скопированный report или подпись schedule её не заменяют.

Для O3 источник явно synthetic, phase-bound и fixture-bound. Свежая synthetic observation создаётся отдельно из принятого fixed fixture с фактическим observation time. Старый реальный O2 broker snapshot не retimestamped. O3 не требует нового FINAM GET и не доказывает фактический брокерский счёт.

Проверяются exact strategy/profile, account alias, instrument/venue/exchange/market, tick, runtime/operational identities, текущая O3 phase и config/plan bindings. Новый permit соединяется consuming seam с authenticated текущим seed. Он не обнуляет paper state.

Отделить исторический bootstrap/recovery receipt от текущего execution permit. Замена timestamps внутри старого receipt некорректна: она ломает его хронологию и может сделать уже закрытый canonical M10 stale относительно фиктивно обновлённого recovered_ts.

Свежесть нового допуска берётся из required Stage4 sources; его действие ограничено deadline текущей phase. Не увеличивать прежние freshness budgets только ради продолжительности O3. Сохранить existing boundary semantics на expires/expires+1.

Свежесть проверяется по реальному времени проверки. Candle-start model time, canonical close и записанное replay/decision time сохраняют разные назначения. Использование старого bar close вместо реального времени для обхода freshness запрещено.

5.3. Exact evidence и deterministic replay

До первого durable commit сохранить exact evidence новой проверки и её canonical binding. Нужна связь с:
- authenticated source seal generation/commitment и Stage6 checkpoint/journal frontier;
- operational identity, profile, account/instrument/tick;
- текущей O3 phase и exact config/plan identity;
- canonical M10 tuple, Redis identity, payload/semantic hashes;
- полным observed source bytes/hash и покрытым catch-up range;
- checked/issued/expiry и записанным decision/validation time.

Источник evidence должен быть воспроизводимым из exact retained bytes через те же production constructors. Одного digest без доступных bytes недостаточно.

Использовать существующие custody/hash/journal/source-evidence механизмы. Защитить binding digest в RequestAccepted source_evidence и соответствующем S1. Если нужна малая additive typed evidence/schema correction, включить её в этот source slice и проверить совместимость старого O2. Новый root, новые ключи/роли, замена общего journal или миграция старого O2 не требуются.

Разделить frontiers:

A. До RequestAccepted.
Новый callback допускается только с действительным новым permit. После сбоя можно восстановить exact retained attempt при тех же identities и ещё действующем допуске; иначе отказ/новая явно проверенная попытка. Ни одного исторического TTL rewrite.

B. После RequestAccepted, до S1.
Реконструкция использует exact proof, candidate и decision time уже принятой попытки. Требуются те же request/command identities и sequence. Нельзя получать другой результат из позднее собранной Stage4 observation.
Истёкший после решения proof не превращается в разрешение нового callback: он используется только как replay authority этого записанного решения, при сохранении обычных phase/guardian/effect checks.
Missing/corrupt/foreign evidence или digest mismatch — отказ без очистки принятого record.

C. После S1/V4, ACK или truth.
Обычный committed recovery, сохранённый provider outcome, S_ack → S_truth → XACK-last. Ни повторной команды, ни нового schedule admission вместо committed proof. Проверить уже принятый response-loss/AlreadyAcknowledged путь.

Replay может заново вычислять прежний callback для реконструкции. Считать отдельно callback attempts и новые логические решения; не требовать фиктивно «один вызов» там, где обычный exact replay действительно повторяет вычисление. Exactly-once требуется для принятого request, публикации и provider effects.

5.4. Observation catch-up

Сохранить existing observation-only first-boot kernel. Все missing covered bars до текущего decision bar проходят без execution intents, request, command, provider action и XACK. Generate-and-discard не подходит.

До mutation проверить весь prefix, overlap и candidate identity. Полный observed source должен быть связан с canonical входом, а не принят только по совпадению последнего close.

Принятая sparse-M1 полнота сохраняется. Отсутствующие минуты не синтезировать; непроверенный пустой M10/holiday/clearing interval не пропускать. Использовать существующий approved schedule/coverage contract; неизвестный interval fail-closed.

История ограничена нужным хвостом сохранённой сессии и закрытой частью текущей, без многомесячного прогрева. Four-day cap оставить только явным fail-closed resource bound, не календарным доказательством.

Не менять модельные session labels и entry/EOD правила. Для первого M10 [07:00,07:10) model label остаётся 07:00, canonical close — 07:10 МСК. Catch-up не сдвигает начало сессии на 07:10 и не отменяет запрет новых входов после 23:30.

5.5. Следующий M10 и bounded lifetime

Одна успешная свежая проверка при старте не означает бессрочный paper-допуск. Existing Stage4 proof O3 имеет короткую свежесть; обычный M10 interval может быть длиннее.

Linked witness обязан проверить следующий M10 с фактически прошедшим временем и явно показать допустимый свежий proof либо штатный refusal. Нельзя сжать/подменить часы, чтобы обе свечи искусственно оказались внутри одного freshness budget.

Если bounded O3 ждёт новый M10 после expiry, новую проверку выполнить через ту же production Stage4→Stage5C цепочку непосредственно перед NEW decision той же phase. Новый proof связать с актуальным seal/frontier. Это продолжение уже admitted paper run с сохранением его виртуального state, а не новый bootstrap flat seed. Ошибка/expiry/current-phase mismatch ведут к остановке в прежней bounded supervision.

Не добавлять универсальное продление, отдельный worker или cross-phase автоматическую readmission. Начальный stopped non-flat seed не открывается этим контрактом; committed recovery продолжает использовать принятые маршруты.

6. МИНИМАЛЬНОЕ ДОКАЗАТЕЛЬСТВО ДЛЯ SOURCE ACCEPT

Один связанный local witness на production constructors, с fault variants, вместо новой большой матрицы независимых формальных assertions:

- Создать V5/O2 seed штатно с локальными test keys и затем пройти authenticated public restart. Старый TTL действительно истёк до O3. Scalar field injection не заменяет этот witness.
- Свежая synthetic Stage4 evidence → typed paper admission → observation хвоста прошлой сессии/текущей → canonical M10 → ordinary Market → provider outcome → S_ack → S_truth → XACK-last.
- Следующий M10, корректная freshness handling и bounded stop. Сохранённый profile и O2 marker/receipt неизменны; нет повторного first boot или исторических заявок.
- Сравнить uninterrupted run с pre-append, RequestAccepted-before-S1 и post-S1/truth-before-XACK restarts. Для journal-ahead варианта показать exact replay после истечения decision proof, пока обычная phase/effect authority допускает recovery, без получения нового решения.
- Отдельно показать no-effect решение и successor после истечения первого proof: успех одного Market не доказывает все Ready paths.
- Прямые counters: observation callbacks, fresh/replay decision attempts, accepted request/sequence, provider/publication attempts и successes, claim/XACK, schedule reads. Final truth и PEL должны совпасть; AlreadyAcknowledged не создаёт дополнительный effect.

Негативные вариации того же witness:
expired/missing/future/foreign fresh admission; неверные account/profile/phase/root/source hash; schedule-only доказательство вместо Stage4 accepted evidence; non-flat initial seed; unknown gap/empty bucket/truncated source/bad tick/overlap drift; missing/corrupt replay proof.

Preset shutdown и SIGTERM/SIGINT handoff из принятого O3 остаются действующими; свежий permit не должен запускать callback после принятого stop.

Проверки: focused new tests и связанные existing first-boot, semantic, journal-ahead, V4/lifecycle, response-loss, signal и parity regressions; fmt/Clippy затронутых crates и production feature set. Exact selection не может завершаться PASS при нуле выбранных тестов. Сохранить полные logs/exit codes и честный список выполненных/пропущенных suites. Перепривязать authority только к завершённой correction после source acceptance согласно существующему процессу.
