6. Следующий узкий scope в облегчённом roadmap

Можно готовить исполнение отдельно разрешённой stopped installation именно
этого ZIP. Минимальный порядок:
1) Проверить ZIP SHA и использовать installer/dependencies/payload этого pack.
2) Выполнить fresh exact read-only preflight, повторяемый под двумя locks.
   Дрейф history/root/P0/custody/inventory — остановка, без тихой перепривязки.
3) Один согласованный apply, затем exact postflight/evidence:
   APPLIED, девять new hashes/custody, retained O2 state/history/receipts,
   P1 stopped, отсутствие reload/start/claim/Redis/bootstrap/signing.
4) Передать компактное evidence фактической установки на приёмку.

Installation PACKAGE ACCEPT сам по себе не является operational installation
permission. После installation evidence ACCEPT отдельно выдаётся разрешение
на одну bounded O3 с fresh phase/window/input bytes, настоящим preserved O2
root и существующим HMAC. Нельзя повторно использовать synthetic/expired
inputs, делать новый O2 bootstrap/root, FLUSH/repair DB15 или скрытые retries.

Operational O3 затем проверяет paper outcome, successor M10, restart без
повторных эффектов и controlled stop. После bounded O3 acceptance — короткий
O4 с FINAM read-only bars/WS, freshness/reconnect/REST overlap/EOD и сравнением
с ALOR freeze, затем отдельно принимаемый FINAM live micro soak.

Узкий комплект достаточен для этого шага. Дополнительные роли, ключи,
control roots, recovery framework, новые design-фазы или обязательный полный
CI/merge на каждый packaging-only шаг не требуются. Точный startup/stop,
custody, durable-before-XACK и replay/idempotency contracts сохраняются.
