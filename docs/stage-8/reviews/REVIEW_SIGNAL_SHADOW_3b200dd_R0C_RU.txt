2. Замечания, требующие исправления

R1 — P2: QUOTES capacity ограничивает суммарное число событий за весь запуск.

Места:
- crates/finam-signal-shadow/src/quote.rs:30–32, 101, 126–151;
- crates/finam-signal-shadow/src/transport.rs:168–191;
- crates/finam-signal-shadow/src/runner.rs:236–245;
- crates/finam-signal-shadow/src/session.rs:229–231.

QuoteInput сохраняет все уникальные timestamps в seen, без освобождения.
ConfiguredTransports задаёт quote_capacity через max_cache_bars, причём значение
не может превышать 4096. QUOTES нормализуется постоянно, даже при flat/no-intent;
проверка pending находится позже, в session.

Детерминированный сценарий по коду: 4097 корректных, свежих, возрастающих quotes
при максимальном лимите → Capacity → Held → runner_quotes_observe → shutdown.
Fail-closed отказ предусмотрен и тестируется; проблема в том, что cache bound
стал лимитом общего количества котировок. Для пути 07:00→23:40 это максимум
одна новая котировка примерно в 14,6 секунды; при условном потоке 1/sec лимит
исчерпается примерно за 68 минут. Фактическую частоту FINAM reviewer не утверждает.

Минимальная правка: отделить quote dedup budget от M10 cache и использовать
ограниченное окно/монотонный frontier. Старое событие после вытеснения не должно
стать новым feedback; сохранить exact-duplicate/conflict/order checks и поведение
через reconnect. Простого увеличения total-count limit недостаточно для
устойчивого bounded stream.

Acceptance правки: >4096 свежих монотонных quotes при ограниченной памяти,
включая flat/no-pending; duplicate/conflict и old-event replay через reconnect
не дают второго эффекта. Текущий tests/quote.rs:78–93 проверяет отказ при
переполнении, но не способность обработать длинный корректный поток.
Закрыть до реального длительного observation.

R2 — P2: independent report IDs несовместимы с текущим config binding comparator.

Места:
- crates/finam-signal-shadow/src/config.rs:33–35, 153–158;
- crates/finam-signal-shadow/src/seed.rs:171–174;

ValidatedConfig хеширует полный ShadowConfig, включая run_id, segment_id и
previous_segment_id. Реальные SeedObservation получают этот полный fingerprint.
report_identities_compatible требует равенства config_sha256. Поэтому одинаковые
model/seed/feedback/inputs с разными FINAM/reference IDs дают NotComparable ещё
до semantic comparison. Комментарий observer при этом ожидает разные IDs.
Существующий тест меняет header IDs вручную, сохраняя фиктивный config hash,
и не воспроизводит production construction.

Минимальная правка: сохранить полный fingerprint для provenance и определить
отдельный строгий semantic comparison binding без attribution IDs. Сохранить
проверки model/reference/seed/feedback/mapping/calendar и всех влияющих на
сравнение параметров. Нельзя просто удалить config check или вручную подменять
hash в header.

Acceptance правки: создать два реальных headers через ValidatedConfig →
SeededSegment с разными IDs и эквивалентными остальными входами; их сравнение
допустимо. Изменение seed/model/feedback/mapping/calendar должно по-прежнему
давать NotComparable. Это исправление comparator, а не закрытие всего S2.

3. Что в реализованной части выглядит корректно

Runner действительно связывает выбранный seed/config с GET-only REST,
отдельными BARS/QUOTES workers, model callbacks, virtual feedback и JSONL.
Worker read futures сохраняются между coordinator selections; ошибка worker
прекращает composition. Shutdown вызывает stop, abort и join под timeout.
При controlled reconnect старый BARS socket уничтожается до открытия нового.

Provisional BARS, handshake и heartbeat не продвигают модель. Finality поступает
из admitted REST ranges. Required nominal sequence, duplicate/conflict/gap checks
и timestamps не заменяются WS health. Raw admitted REST evidence записывается
до выбранного model advancement.

Используется настоящий HybridIntradayRuntimeStrategy и фиксированный
baseline07 BO-only/no-riskgate профиль. Intents создают virtual pending;
position callback меняет последующее состояние модели. Quote event time <=
measured callback result не заполняет новый intent. Ошибка timing/callback
делает путь terminal, без rollback/retry. EOD exit intent не равен flat;
pending/nonflat/missing due bars заканчиваются INCOMPLETE.

Историческая проверка использует pinned input и независимые frozen Python
rounds, но synthetic-close feedback отличается от observed QUOTES policy.
Отсутствие полного независимого state/reason parity описано честно.
Ложного полного parity-PASS в проверенных paths не обнаружено.
