4. Достаточность fault-тестов

Файл:
crates/runtime-durable-service/src/stage8b_p1_semantic/redis/tests/observed/o3_readmission/sync_retry.rs

Четыре варианта проверяют успешный retry и отказ на трёх границах:
до file sync, до parent sync и до final reread.

Первая попытка проходит штатный process_next и полностью выполняет
write_all proof, затем тестовая barrier возвращает ошибку до fsync.
Проверяются отсутствие callback/publication/provider/XACK и неизменность
реальных journal/seal. Повторная попытка идёт через публичный Ready restart,
с тем же durable root, proof и pending M10 в disposable Redis.

Успешный вариант проверяет порядок FileSynced → ParentSynced →
ExactReread → CommitEntered → CommitReturned, один логический callback
и изменение journal/seal до обычного Prepublication. Это не полный тест
цепочки publication/provider/XACK: положительная ветвь останавливается
на Prepublication, а последующие участки покрывает сохранённая регрессия.

При трёх отказах проверяются нулевые эффекты, byte-for-byte сохранность
journal/seal/history/proof, единственный прежний proof path и тот же
Redis PEL id. Повторное открытие root остаётся Ready.

Ошибки инжектируются непосредственно перед операциями. Тесты не создают
реальный kernel EIO и не моделируют физическое отключение питания.
Успешная ветвь вызывает настоящие sync_all и reread. Production-вызовы
пропускают реальные Err через ? до commit. Для согласованного минимального
доказательства этой границы указанных тестов достаточно.
Все новые fault/trace hooks и re-export защищены #[cfg(test)];
в production library они отсутствуют. Новая fault-матрица не требуется.
