# Stage 8B-P R2A4 review closure

R2A4 is a corrective, no-real-network candidate. It addresses the independent
R2A3 findings without opening R2B, Stage 8B-XE or an order-effect surface.

## Closed findings

1. Eleven issuer-owned receipt directories replace the contradictory shared
   owner model. Numeric systemd instances derive source identity from effective
   UID; caller arguments cannot redirect authority.
2. The Ed25519 run package binds the exact run identity, manifest, account HMAC
   and generation manifest, build/helper/contract, trust set, eleven source
   generations, operator decision, operation, issuance and expiry.
3. Production source and authorization public keys have a root-owned pinned
   trust manifest, aggregate key-set digest, generations and validity windows.
4. Eleven producer binaries read source-specific root-owned authoritative-store
   records, enforce closed schemas, consume monotonic generations and publish
   atomically before separate issuer UIDs sign them.
5. A production key ceremony generated public manifests and external 0600
   private material. Rotation requires a newly reviewed package.
6. The fixed-path Linux rehearsal runs all 22 identities, exact package issuer,
   nonce registry, fd-bound launcher/helper and complete controlled PLACE and
   CANCEL TLS sequences.
7. The pinned Linux/amd64 Rust builder produced two byte-identical builds for
   every binary. Compiler, Cargo, linker, dependency graph, source identities
   and binary hashes are recorded in the build evidence.
8. The account key manifest maps generation to exact path, fingerprint and
   validity. Secret files use strict one-line grammar and fd-bound no-follow
   reads; nonce consumption occurs only after local validation.
9. Exact/list order equality includes execution ID, executed/remaining
   quantities and accept/transact/withdraw timestamps.
10. The focused negative harness rejects all 32 R2A4 authority mutations.

## Deliberately closed

- production run package status remains `NOT_ISSUED`;
- real FINAM credentials, AuthService POST and broker GET remain forbidden;
- FINAM order POST/DELETE, operator arm, dispatch attempt and effect transport
  remain forbidden;
- Redis execution, runtime-live and real strategy orders remain forbidden.

Independent acceptance of R2A4 may authorize only a separate exact R2B
read-only evidence package. It does not itself authorize any network request.
